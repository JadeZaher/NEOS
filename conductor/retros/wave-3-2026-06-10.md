## Per-stream outcomes

### S1 — exec_tool (Python/Node sandboxed script execution)

Finished the 3-of-7 partial deliverable. Added `exec_tool.py` async entry point, `registry.py` decorator-based registration (no modification to `governance_tools.py`), 26-test pytest suite, SECURITY.md with 5-threat model.

**Code review surfaced 3 silent-failure security bugs**:
- `resource.setrlimit` was called with a 1-tuple, raising `TypeError` on every Linux execution — RLIMIT_AS and RLIMIT_CPU mitigations **never applied in production**. Tests passed because Windows lacks the `resource` module entirely. **Tests were running on a code path that doesn't exist in production.**
- `PYTHONPATH` and `VIRTUAL_ENV` were leaking through `_MINIMAL_ENV`, letting an LLM-generated script prepend `sys.path` entries and bypass the import allowlist scanner. **Complete defeat of the primary T1 mitigation.**
- Post-timeout pipe drain called `proc.communicate()` on an already-cancelled coroutine — undefined behavior, deadlocks when OS pipe buffers are partially full. **Could hang the entire agent event loop indefinitely.**

Also added `exec()` / `eval()` detection (closes a known T1 residual risk), `shutil.rmtree` cleanup (subdirs were leaking), and three new negative-security tests for the bypass surfaces. Final: 29/29 tests pass.

### S2 — Emergency Half-Open patch (PRODUCTION)

Reviewed and finalized the open→half_open→closed state machine. Originally 5 modified + 2 new files (+209/-7), expanded in review to 16 fixes including a **critical migration bug**:

**Migration 009 assumed `emergency_states` already existed — but no prior alembic revision creates it.** Dev/test environments survived because they bootstrap via `Base.metadata.create_all`. **A clean-DB `alembic upgrade head` would have raised `NoSuchTableError` at `op.add_column`.** The L2 reviewer rewrote 009 as idempotent: creates table if missing, normalizes legacy `state='resolved'` rows before installing the CHECK constraint, guards every DDL with existence probes, symmetric guards on downgrade.

State machine hardened further:
- `SELECT FOR UPDATE` row locks added to `resolve_emergency`, `complete_recovery`, and the cron `_auto_revert_emergencies` path. The original code allowed a cron-vs-API race that could double-transition a single record.
- State vocabulary centralized as `STATE_OPEN`, `STATE_HALF_OPEN`, `STATE_CLOSED`, `ACTIVE_STATES`, `RECOVERY_WINDOW_DAYS` constants. Cron imports them from the API module.
- `declare_emergency` blocks duplicate active emergencies (the API path didn't; was asymmetric with `governance_tools.declare_emergency`).
- `governance_tools.declare_emergency` now uses `state.in_(ACTIVE_STATES)` instead of `state != "closed"` (forward-compatible if a "suspended" state is ever added) and initializes `actions_log` with a structured `'declared'` entry + `pre_authorized_roles=[]`.

Final: 46/46 tests pass (12 emergency + 24 governance + 10 new).

### S3 — Codegen pilot (SKILL.md → tool generator)

Generated 10 new tool stubs, fixed 4 parser/validator/manifest gaps:
- Type inference heuristics (`_NON_ID_PATTERNS`, `_TYPE_PATTERNS`)
- Optional-input detection (10+ contextual phrase patterns)
- Capture-vector regex with slashes
- AST-based ToolDef extraction replacing regex (handles `AnnAssign` and nested braces; extracts 29/29 tools)

**Review surfaced that all 13 generated stubs failed `py_compile`** — two bugs:
1. `\U` unicode escape in Windows path docstrings (`Source: C:\Users\...`)
2. Top-level `def get_*_tooldef()` and `*_TOOLDEF = ToolDef(...)` emitted at 8-space indent

The current generator (post-L3-redo + the path fix) produces clean Python — verified by rendering a fresh skill. **All 13 stubs were deleted from the working tree** rather than regenerated, because the user surfaced a wave-4 architectural redirection that makes the whole pipeline obsolete:

> *Architectural insight (captured for wave-4)*: The codegen's brittleness is upstream — it tries to extract structured intent from unstructured prose. Split `db/models.py` into one file per model. Make SKILL.md a YAML-frontmatter document where structured fields (inputs, types, optional-ness, model reference, target tool name) live in a parseable header. Rewrite the codegen to read the YAML directly. Drift detection becomes "compare YAML to ORM schema" — both sides structured, no AST walk needed.

This eliminates every parser heuristic the L3 fixes were patching.

## Methodology lessons (carry forward)

### The `code-reviewer` agent class has no Edit/Write tools

Catalog reads: "Tools: Read, Grep, Glob, Bash". L1 hit this and got stuck in a generation loop trying to write fixes it couldn't write. L3's first attempt died silently the same way. L2 and L4 worked around it via Bash heredocs. **For review-with-fix workflows, use the `executor` agent (which has Edit/Write) and have it consume a findings document the reviewer produced separately.** Or use `executor` for both review and fix in one pass — it has the capability.

### "Tests pass" ≠ "production code works"

S1 ran 26/26 pytest green, and the executor reported "complete" with confidence. But the test process never exercised the Linux-only code path containing the silent `setrlimit` failure. **A test that exists on Windows but exercises Linux-only behavior is not actually a test.** Verification briefs for next waves need to require: (a) tests run on the production OS, or at minimum (b) explicit OS-guard tests that fail loudly when an expected path is skipped.

### Verify emitted artifacts, not artifact count

S3 reported "10 of 10 skills generated" and the executor confirmed file counts. **Nobody ran `py_compile` on the outputs.** Wave-3 shipped 13 Python files that couldn't even parse. **Next-wave verification briefs must require syntax-check (py_compile or equivalent) on every emitted artifact, not just count.**

### pi-bridge `--model` flag silently wedges sessions

Documented in the wave-3 brief, validated in practice: not passing `--model` (so pi inherits from `~/.pi/agent/settings.json`) kept all 5 wave-3 sessions healthy. Worth keeping in any future ultrapilot brief.

### Pre-baked speculative integration works

S5's `CompleteRecoveryDialog` was built before S2's backend route was committed. The SPECULATIVE comment captured the integration-time reconciliation task. At review, the response-shape gap surfaced cleanly — the SPECULATIVE marker did its job. **Pattern worth repeating**: when stream A depends on stream B's in-flight output, build A speculatively from B's working-tree state with a load-bearing comment that the reviewer/integrator must address.

### Atomic per-submodule commits scale poorly past 3 streams

Wave-3 had 4 streams in one submodule (S1+S2+S3 in neos-operating-system) and 1 in another (S5 in charting-the-course). Single-submodule commits bundle mixed concerns — the wave-3 build commit had production migration + scratch experiments + sandboxed exec tool in one diff. **Per-stream commits would have been cleaner**; the consolidated-per-submodule choice was the right call for review velocity but is harder to revert selectively.

### The SQLite swarm pattern was unused

The `/swarm` skill's atomic-claim layer is overkill when lanes are pre-partitioned with disjoint scopes. The 4-lane review ran as 4 parallel agents with hardcoded scopes, no contention possible. The SQLite pattern earns its complexity when N is unknown or work is uniform/homogeneous; for fixed-N heterogeneous lanes, plain parallel `Agent` calls are simpler.

## Architectural insights (load-bearing for wave-4)

1. **Codegen v2 — YAML/model-path** (user's proposal, captured above). Eliminates the parser-heuristic class of bugs entirely.
2. **`db/models.py` should be split** — currently 113 KB monolith. Beyond enabling codegen v2, splitting unblocks parallel model edits and makes the dependency graph readable.
3. **The agent's `code-reviewer` agent definition should be reviewed** — missing Edit/Write tools means it can only critique, not fix. Either add the tools or rename the agent so the limitation is obvious (e.g., `code-critic`).
4. **Wave-3 commit verification was insufficient** — the executor briefs trusted self-report. Going forward, verification should be a separate pass (the role this wave's review played) but ideally automated as part of the dispatch contract: no "done" without disk + syntax + test evidence.
