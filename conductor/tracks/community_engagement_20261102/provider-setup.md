# Protected runtime variables
Common:
- ENGAGEMENT_EXTERNAL_ENABLED=false until the approved activation.
- ENGAGEMENT_EMAIL_ENABLED=false, ENGAGEMENT_PUSH_ENABLED=false, ENGAGEMENT_SMS_ENABLED=false independently.
- ENGAGEMENT_PUBLIC_URL: canonical HTTPS frontend base, e.g. https://neos.primusneo.com.
- ENGAGEMENT_API_PUBLIC_URL: canonical HTTPS API base, without trailing API path.
- ENGAGEMENT_SIGNING_SECRET: independently generated stable random secret of at least32 characters; used for keyed verification and unsubscribe signatures. Rotation invalidates outstanding unsubscribe links and codes, so treat it as persistent.
- ENGAGEMENT_WORKER_INTERVAL_SECONDS=15; the loop bounds fanout/queue work and max10 dispatches per cycle.
- ENGAGEMENT_SEND_TIMEOUT_SECONDS=15; actual transport deadlines remain shorter than the90-second claim lease.

Email:
- RESEND_API_KEY: sending permission for the verified domain.
- RESEND_FROM: approved display name/address, e.g. NEOS Community <updates@updates.YOUR-DOMAIN>.
- RESEND_REPLY_TO: optional monitored support address.
- RESEND_WEBHOOK_SECRET: dedicated signing secret from the endpoint setup.

Push:
- VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY: same locally generated stable pair, kept server-side except public key exposed by authenticated capabilities.
- VAPID_SUBJECT: real operator mailto: address or HTTPS contact URL.
- Regenerating VAPID keys requires browser re-enrollment; keep the pair stable.

SMS:
- TWILIO_ACCOUNT_SID.
- TWILIO_API_KEY_SID and TWILIO_API_KEY_SECRET for outbound REST.
- TWILIO_AUTH_TOKEN for signed inbound callback validation.
- TWILIO_MESSAGING_SERVICE_SID and TWILIO_VERIFY_SERVICE_SID.
- No profile-phone value is automatically enrolled or treated as verified.

# Resend account and DNS steps
1. Create/select the account and choose a sending subdomain under a domain you control.
2. Add exactly the DNS records generated by Resend, wait for verification, and confirm the From identity is approved.
3. Disable open/click tracking for this sender domain. NEOS adds no tracking pixel.
4. Create a sending API key and configure the protected variables.
5. Configure a webhook at ENGAGEMENT_API_PUBLIC_URL + /api/v1/engagement/webhooks/resend for delivered, bounced, complained, failed, suppressed and delivery-delayed events. Save the signing secret.
6. Keep both global and email flags false until the owner supplies an approved initial test address and authorizes activation.
7. Activate only email, use the owner's signed-in settings to request ownership verification, verify the actual code, then explicitly enable email and follow a test scope.
8. Produce a new authorized test occurrence after activation. Do not import an old notification backlog. Confirm accepted state and actual signed delivered callback separately.
9. Test unsubscribe from the actual email: GET renders a confirmation without changing state; signed POST disables delivery. Re-enrollment requires a new verification generation and explicit channel enable.
10. Monitor provider quotas and the local retry/dead/ambiguous states. Resend's free plan is100/day; select the appropriate plan before broad community activation.

# Web Push activation
The stable VAPID pair and signing secret have already been generated and stored in protected Railway variables, with VAPID_SUBJECT=https://neos.primusneo.com. Do not regenerate them during provider setup. No notification SaaS account is required. Native push remains explicitly disabled pending owner-approved activation and a test browser.
The browser enrolls only after an explicit action. A device binds to the actual authenticated session. Logging out disables that session's devices; other signed-in devices remain independently enrolled. Browser/account changes must clear old registrations before re-enrollment. Dispatch requires an unexpired same-owner session.
Supported push host families are explicit: Google's FCM, Mozilla Push, Apple Web Push and Windows notify hosts. Unknown services fail as unsupported. Endpoint validation runs during enrollment and send, including DNS global-address checks and no redirect following.
Send one owner-approved generic test update after activation. No private message bodies or private titles appear on the lock screen.

# Twilio setup and opt-out
1. Create/configure the Messaging Service and approved sender for intended regions. Complete any provider-required sender registration.
2. Create a Verify Service and configure API credentials plus the callback auth token.
3. Set the Messaging Service's inbound callback and delivery callbacks to ENGAGEMENT_API_PUBLIC_URL + /api/v1/engagement/webhooks/twilio. Enable Advanced Opt-Out.
4. Verify the fixed externally configured HTTPS callback URL matches exactly; proxy Host headers do not alter signature validation.
5. Activate only after the owner approves the initial test number. The member must request actual phone verification, enter the approved Verify code, then explicitly enable SMS and a follow.
6. STOP suppresses all matching stored generations of that exact number and disables their SMS preferences. START clears only sms_stop suppression, clears ownership verification and leaves SMS off. Fresh verification and explicit enable are required.
7. Hard provider suppression is never silently cleared by preference updates.

# Delivery and failure semantics
Daily digests are due09:00 and weekly digests Monday09:00 in the member's IANA timezone. Quiet hours and pause shift the due time; DST is evaluated from UTC instants. Identical quiet start/end means no quiet interval. In-app reading excludes a digest item before its first attempt; after an uncertain send the immutable manifest/body/key is retained. Reading an update is not governance completion.

Each device has independent push consumption. Email/SMS consumption is per recipient/event/channel. One channel does not consume another's update. The first attempt freezes the generic body, event manifest and immutable contact generation. Changes in current permission, consent or destination suppress retries; a frozen body is never rewritten under an existing provider idempotency key.

Expired started SMS/push attempts become ambiguous and are not blindly resent. Resend retries use the same frozen body and idempotency key within a conservative23-hour window (provider retention24hours). Stale worker completions fail claim-token comparison. Provider acceptance is not a delivery receipt. Delayed signed callbacks cannot redirect old destination suppression to a new contact.

Webhook receipts arriving before their corresponding provider response has been persisted return retryable503 instead of being permanently consumed. Dedicated callback endpoints should only receive NEOS events, so unrelated account-wide messages do not create persistent unmatched retries.
