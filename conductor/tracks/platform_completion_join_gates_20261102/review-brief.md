# Shared acceptance snapshot

Read spec.md, decision-ledger.md and verification.md in this directory. Both branches of each cycle receive the same source snapshot and file-hash manifest. Authors must finish their current batch before snapshot capture; no source mutations occur while the two branches inspect it. The cycle-two manifest follows the accepted cycle-one revisions.

Keep the entire scope: configured-only quiz prerequisites, authentic grading, NodeAdmin quiz exemption and configured roles, memberless support navigation, real owner-private tool-free orientation, governed consent-aware matching, the five ordinary personal-operator workflow families, structured authoring/reference controls, audit UTC and verified legacy cleanup. Historical author permissions stay compatible. An ordinary entrant does not inherit a quiz exemption merely because an admin submits the request, although a deliberate reasoned support correction is available and audited.

## Branch output

Return at most three actionable findings with file:line evidence, a concrete failure or improvement, user impact and a proposed verification. Do not invent issues to fill the quota. Distinguish observed code facts from hypotheses. Report which parts were actually inspected and any limitation. Source review happens before the integrated sweep, so authored-but-unexecuted tests are not evidence of a passing runtime.

The advocate should identify the strongest useful interpretation and small changes that make it reliable; the adversary should find counterexamples and unsupported claims. Neither may relax authorization, privacy, confirmation or correctness. Trace actual call paths rather than inferring protection from a function's name. Read-only branches may inspect source and captured artifacts, but must not edit, run the integrated test sweep, change the stack, invoke models, contact people or write to production.

## Required safety questions

- Can any signup, activation, subgroup, agent or rejoin path skip a configured quiz for an ordinary entrant? Does explicit NodeAdmin exemption disappear on revocation without fabricating a result or destroying existing participation?
- Are answer keys, caller identity, old attempts and cross-scope references controlled by the server? Does the UI have a usable return/recovery path?
- Do private orientation and matching data stay private across users, ecosystems and admin-support surfaces? Is published matching configuration governed, versioned and actually configurable from the product?
- Do ordinary tool writes use actual caller authority, shared lifecycle validation and exact previous-turn frozen confirmations with one-use execution? Are reads and exported links bounded by the same privacy rules?
- Can a memberless NodeAdmin find every new task, select real configured roles and produce a meaningful public receipt without gaining fabricated governance identity?

The coordinator synthesizes both outputs, records accept/reject/defer reasons, assigns one author for justified revisions and then captures the next snapshot. Exactly two cycles are authorized by this drive. Final runtime flows and proportionate integrated validation remain required after the revisions.
