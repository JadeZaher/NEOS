# NEOS - UX study

## Product

NEOS (New Earth Operating System) is a governance platform for intentional
ecosystems (OmniOne, Oasis, Escherbridge, Plan Systems). Members orient into an
ecosystem's ethos, put forward proposals that move through the ACT process
(Draft -> Advice -> Consent -> Test -> Ratified), ratify agreements, join domains,
publish shares and needs across ecosystems, resolve conflicts through harm
circles, declare emergencies, and keep a personal decision ledger. Stewards and
admins run onboarding ceremonies, audits, compliance and content. The binding
UX contracts are `GOVERNANCE-ECOSYSTEM-MATCHING-UX-GUIDE.md` and
`GOVERNANCE-ECOSYSTEM-MATCHING-QA-GUIDE.md`; the flow map is `QA-USERFLOWS-GUIDE.md`.

## Target environment

- **Base URL:** http://localhost:5173 (Vite, proxies `/api` to the API on :8000). Test environment ONLY.
- **Database:** isolated local Postgres 16 `neos_uxqa` on `127.0.0.1:5433`, built by `create_all` + `alembic stamp head` + `scripts.seed_all` (2026-10-31). Railway is never touched: every study process exports a local `DATABASE_URL` that overrides `neos-operating-system/agent/.env` (which points at Railway).
- **Guard:** `GET /api/v1/health` -> `status` must equal `healthy`; host must be local. Deny-listed hosts: `rlwy.net`, `railway.app`, `up.railway.app`.
- **Second guard (adapter):** `seed.py` refuses unless its own `DATABASE_URL` is `127.0.0.1:5433/neos_uxqa`; after seeding, `verify-target.mjs` reads the `uxqa_environment` sentinel setting through the running server with a persona session, so a server pointed at any other DB fails closed.
- **Mail:** NEOS sends no email. Web push goes only to stored push subscriptions (seeded ones are fake endpoints). AI chat calls OpenRouter with the developer's key (real, small cost).
- **Who owns it / how it is reset:** the coordinator. Start: `bash uxqa/adapter/stack.sh api` and `... web` as tracked background jobs. Backend fixes need an API restart (single-process, no reload); frontend fixes are live via Vite HMR. Full reset: drop and recreate `neos_uxqa`, then repeat the bootstrap.

## Session adapter

- Seed: `bash uxqa/adapter/adapter.sh seed {personas} {out}`
- Link: not supported (no magic-link flow); `adapter.sh link` prints `REFUSED`.
- Handle rule: `^qa-[a-z0-9-]+$`; username = handle with `-` -> `_`.
- Persona `seed`: `{ "anonymous": true }` for a signed-out visitor, otherwise `{ "memberships": [{ "ecosystem": "OmniOne|Oasis|Escherbridge|Plan Systems", "role": "user|mod|admin|owner", "profile": "townhall|collaborator|builder|co_creator", "status": "active|prospective" }] }` (default: one active OmniOne `user`/`townhall` membership).
- Every seed resets each persona's display name/bio/headline, orientation progress, domain participations and active shares, expires old sessions, and withdraws `(uxqa gold)` proposals, so gold tasks start from the same state each pass.
- Sessions file: `uxqa/.secrets/sessions.json` (gitignored; never printed).

## Routes and API

- Routes dir: `uxqa/routes` (generated by `node uxqa/adapter/gen-routes.mjs` from the wouter `<Route path>` list in `charting-the-course/client/src/App.tsx` plus the live Sanic route table), framework `next-pages`. 76 pages, 134 API routes at setup.
- API style: REST under `/api/v1/`.

## Gold tasks

| id | persona | goal (user words) | success |
|---|---|---|---|
| gold-signup | qa-visitor (signed out) | Make yourself an account and get into the app | URL `/dashboard` |
| gold-propose | qa-gold-member | Put forward a proposal titled "Shared tool library (uxqa gold)" and open it for advice | proposal page + advice-phase banner + that title |
| gold-advise | qa-gold-advisor | Give advice on a proposal waiting for it, including "uxqa gold advice" | advice text visible |
| gold-orient | qa-gold-newcomer | Start the orientation journey for an ecosystem you are curious about | URL `/orientation/<slug>/journey` |
| gold-share | qa-gold-member | Publish a public offer "Seed saving workshops (uxqa gold)" and check it is listed | title visible |
| gold-profile | qa-gold-advisor | Change the name other members see to "Rowan Uxqa-Gold" | new name visible |
| gold-respond | qa-gold-advisor | Find Escherbridge's public need "Rainwater harvesting help (uxqa gold)" and message its author (added 2026-11-01, wave C; the seed's `ensure_gold_need` keeps it open and `forget_post_responses` makes every run a new conversation) | "Message sent to" visible |

Known limit: `gold-advise` can be satisfied by opening an older proposal that
already carries "uxqa gold advice" in its log (the first advice auto-advances a
proposal to consent, so old ones leave the advice list). Triage checks the
`ux.json` steps of any gold-advise success that made no POST to `/advice`.

## Agent evals

Each pass also runs the in-app assistant through 25 fixed tasks (read, act,
must-refuse, clarify, plain language) in the plugin's optional AgentEval phase,
after Metrics and before the Panel: `node uxqa/agent-evals/run.mjs <pass>` seeds
its own `qa-agent-*` personas with member resets only (gold proposals stay),
builds `uxqa-p<N> agent-eval` fixtures through REST, drives the real
`POST /api/v1/chat/send`, grades API state first, then the tool trace and text,
and a Sonnet judge only where those cannot decide, and writes
`passes/<pass>/agent-eval.json`; failed tasks reach triage as `agent-eval`
defects. It is the one exception to the two-assistant-messages-per-lane rule,
bounded by `agentEvals.tokenCap` (1.5M tokens, about cents on the default model)
and 30 minutes. Tasks, check grammar and teardown: `uxqa/agent-evals/AGENTS.md`.

## Safety rules (in addition to the plugin's reference/safety.md)

- Never send chat messages to the AI assistant more than twice per lane (real OpenRouter cost); never paste persona data into it.
- Never declare an emergency, trigger an exit, or change member roles except in a lane whose scenario explicitly covers it, and only on qa-* personas.
- Never modify `neos-operating-system/agent/.env`, `charting-the-course/.env`, Railway, or the `neos_uxqa` bootstrap; never point anything at `*.rlwy.net`.
- Fix lanes and the integrator never stage or commit the user's pre-existing WIP files (see `extraRules`).

## Verification commands (re-run by the coordinator, never trusted from agents)

- Tests (backend): `cd neos-operating-system/agent && DATABASE_URL=sqlite+aiosqlite:// PYTHONIOENCODING=utf-8 py -m pytest -q -p no:cacheprovider tests`
- Tests (frontend regression flows): `for f in uxqa/regression/*.mjs; do node "$f" || echo "RED $f"; done` (the frontend has no unit-test harness)
- Typecheck: `cd charting-the-course && npm run check`
- Build: `cd charting-the-course && npm run build`
- Known-red baseline: `uxqa/baseline-red.md`
