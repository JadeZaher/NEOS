## Product gaps requiring source triage

1. **High candidate: required real-guide conversation does not survive reload.** Two successful provider replies disappeared after reload (including a second check after a 2-second settled wait); Continue reverted to disabled, and owner conversation history showed no saved conversation. Completing the step after the requested reload was impossible within the allowed two-message budget. UI observation does not determine backend root cause.
2. **Medium: consented directory profile links reach 404.** Tess link navigated to `/profiles/a0080045-34dc-4ea4-8ba2-b344b1c9e30b`, which renders the app 404. Contact composer route works. Evidence: matching run `directory-profile-404.png` and trace.
3. **Medium candidate: final support review falls back to raw serialized content.** Quiz review shows Survey json with the complete serialized schema and answer key. Journey review shows Content sequence JSON including quiz UUID and Exit package JSON, although authoring uses readable structured controls and a named quiz selector. The human-readable preview does not include the selected quiz name. No raw IDs/JSON were entered by the lane.
4. **Accessibility findings:** Amara's settled ecosystem detail scan after creating the separate journey returned serious `aria-hidden-focus` on two nodes. The required orientation journey returned serious `aria-progressbar-name` on one node, repeated in both settled scans. Ethos scans were clean. Exact nodes are intentionally not inferred from source; inspect the saved traces for triage.
5. **Navigation friction:** returning from a public audit receipt resets support organization and search; selecting same-route Node Administration from the mobile sidebar leaves the sidebar overlay open until Escape. These were recoverable with visible UI/browser navigation.

## Harness and evidence limits

The node_repl runtime cannot import this harness because `process` is undefined. Execution therefore used a persistent local Node stdin driver, retaining commands under `flows/admin-matching-ui/actions.log`; `driver.mjs` is saved beside it. Browser interactions are instrumented by uxSession. Selector errors from the interactive driver were surfaced during execution but are not counted as s.attempt failures; no silent application reset occurred. All tasks stayed below the three manual recovery attempts for an individual action. Browser Back was used after a headless Alt+Left did not navigate; no pointer interactions were used for keyboard-only Ines.

Sana and Tess axe scans had zero violations; matching scans had zero. Amara and orientation each had one unique rule as above. Automated checks do not establish screen-reader usability or informed human consent. No service/provider failure was simulated, and a provider-unavailable UI state was not exercised. Cross-user private history isolation was not established by this UI lane because owner history persistence already failed; separate security probes remain separate evidence.

No full test/lint/typecheck/build sweep was run by this UI lane. The coordinator owns source triage, fixes, independent review and final integrated verification. Traces and screenshots remain ignored local artifacts and contain synthetic private journey content; only outcome metadata is recorded here.
