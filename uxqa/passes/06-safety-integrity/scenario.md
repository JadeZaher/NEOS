# Situation

People join an ecosystem and its circles and teams, complete configured learning requirements, then use the personal operator to carry out real governance work. A separately assigned platform admin helps users, configures quizzes and assigns supported ecosystem roles from an obvious administration page. All writes use the isolated local study database and synthetic qa-* identities.

Keep all prior gold tasks and recorded unresolved questions. This pass adds the complete November 2 source audit scope, rather than replacing it with a quiz-only check. Historical failed runs remain unchanged. The owner chose configured-only quiz gates and explicitly exempted platform admins from quizzes. A builder/co-creator profile or ecosystem steward role alone does not grant that exemption.

## UI journeys

- A newcomer joins an ecosystem with no entry quiz and sees no invented requirement. A second newcomer encounters a published entry quiz, fails once, receives actionable feedback, then passes and returns to the original join context. When explicit agreement consent is also required, both completion orders reach the same correct status.
- A member joins a circle with an ancestor and target quiz, then a team with a distinct quiz. The displayed scope names, remaining requirements and return links explain the next action. Keyboard-only, 390 px and 200 percent zoom variants must work without raw identifiers.
- A memberless NodeAdmin finds administration from the normal navigation, chooses users/ecosystems/memberships/onboarding/audit by task, configures a scoped quiz through question fields, assigns a supported ecosystem role, and reviews the resulting public receipt. The admin's own join bypasses quizzes without fabricating a pass. An ordinary builder sees no equivalent privileges.
- A newcomer talks with the real orientation assistant, reloads their own history and encounters an honest unavailable state when service access fails. A failed/canned response must not complete a required step. A second user cannot read the conversation.
- A member chooses directory/contact/matching consent separately, sees understandable coverage and fit reasons from a governed profile, changes answers and recognizes stale evidence. Opting out removes directory visibility. Missing data offers an actionable completion path.
- A steward authors and previews a journey using structured steps and an exit package. A support operator chooses related records by recognizable labels, reviews exact changes, cancels once, then submits an audited correction.
- Ordinary members use messaging, collaboration proposals, audit publication, exit follow-through/export and conflict/repair actions through the personal operator. The UI identifies the actual actor and scope, resolves ambiguous names, freezes consequential confirmations and gives usable record links. All messages target synthetic QA participants only.

## Separate adversarial probes

Probe quiz answer-key visibility, forged client scores, caller/attempt substitution, old-content passes, unpublished requirements, unrelated-scope passes, rejoin, steward activation, team additions and agent joins. Repeat equivalent checks with an explicit NodeAdmin and with a builder lacking NodeAdmin. Verify role revocation removes exemption on the next request and never demotes historical active memberships automatically.

Probe cross-user orientation history, tool availability, prompt-injected governance requests, private matching data, opt-out withdrawal, coverage thresholds, stale assessments, role escalation, support evidence immutability and exact confirmation replay. Public UTC audit times must represent the same instant in multiple time zones without changing private snapshot encoding.

## Evidence boundaries

UI lanes use only visible navigation and controls, record every workaround, keep bounded attempts and save traces. Fixture creation and API/security probes are labeled separately and never count as user success. Service failures, fixture drift and harness failures are preserved with their actual cause. No real production governance activity is seeded. Automated findings are not human research; open research questions retain a five-session-per-segment validation plan.

The full integrated test/typecheck/build sweep runs after all fixes, per owner preference. An independent reviewer must evaluate the finished source before publication. Two consecutive passing passes are required to claim study convergence; one repaired probe or a subset of old gold checks cannot substitute for that evidence.
