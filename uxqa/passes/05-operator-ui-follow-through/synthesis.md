All seven gold journeys completed on their first instrumented run. Normal assistant help now gives the verified profile route, keeps conversations/drafts across navigation, and removes the old advice cutoff claim. The independently judged 26-task operator baseline passed 23 tasks (88%), with all seven refusal categories preserving their protected states in both repetitions. These results do not establish convergence: the baseline contains one actual wrong-organization write, and retained failed support journeys raise aggregate friction to 16.375.

## Confirmed findings and repairs

The baseline C3 created an OmniOne draft before the user chose Oasis. The first targeted follow-up prevented that write but still invented a recurring event. The second targeted follow-up uses authenticated user words, waits for the organization, and creates only a faithful Oasis draft. It passed independent persisted-content judging at 5/4/5 with zero state violations and no generation-model calls. Earlier failures remain unchanged in their own directories.

The support REST probe exposed an HTTP500 on a valid correction. Refreshing the updated ORM row before serialization/private snapshots repaired it. Independent follow-up verified correction, stale-version refusal, failure audit, UUID-reference lookup, evidence archival, exact restoration and cleanup. The raw probe's 401-versus-404/405 assertion is retained with the independent interpretation and unchanged audit readback; it was a denied write, not an audit mutation.

The original memberless assistant journey failed on incomplete catalog information and unsupported fields. Later follow-ups exposed prose-only approval and then an allowlist failure. A compact complete catalog, targeted writable schemas, canonical resource/action enums and a dedicated typed proposal-preparation tool resolved the core flow. Follow-up 3 reached a server-generated exact review, accepted the user's Yes once, created one draft, and exposed a public receipt with the actual operator, target organization, public category and safe field names. Actual Node Administration readback confirmed the record. Its ordinary proposal receipt link hit a Member gate; the final support-console link and Member-only query gating then passed both the deterministic regression and a real-backend browser probe. The real probe isolated the correct draft, performed no automatic private inspection, recorded one explicit reasoned inspection, and made zero identified Member-only requests.

## Research interpretation

- **Trust and action status:** a correct-looking prose review is insufficient. The operator must prepare an actual server-held action and clearly distinguish preparation, approval, completion and refusal. The staged/frozen architecture now enforces this; human comprehension still needs observation.
- **Information architecture:** a broad resource catalog became unusable when model-budget trimming removed entries. Compact discovery plus targeted writable schemas and typed common actions reduce guessing without granting model authority.
- **Cross-organization work:** an ecosystem cookie or model argument cannot substitute for a user's target choice. Explicit choices, current access checks and one-use staging are necessary even when the operation creates only a draft.
- **Accessibility:** natural keyboard navigation reached exit guidance and consent positions, and 390px read continuity held. Other advisor tasks used assisted focus. No axe scan ran, so this is limited journey evidence rather than a WCAG approval.
- **Content quality:** P1 remains above the grade-8 heuristic. R1 twice stated correct facts but failed wording checks; future matcher contracts now accept those bounded equivalents while preserving negative cases. Neither historical failure was silently regraded.
- **Measurement:** retain all blocked support runs, navigation errors, resource failures and protocol caveats. Later repairs close source findings but do not turn the historical pass into a clean interaction sample.

## Human validation plan

Run five sessions each with new/simple-language readers, keyboard-only users, and support operators helping another organization. Observe first attempts at choosing scope, interpreting the public reason category, reviewing a proposed change, confirming it, following the receipt and finding the saved conversation. Test the welcome video under an ordinary network before attributing the repeated restricted-network failure to application code.

This was the second full iteration of the bounded drive. Native implementation, UI/probe and independent review lanes replaced the unavailable Workflow tool. Source verification (see `verification.md`) and release evidence are separate from the unmet two-consecutive-pass study criterion.
